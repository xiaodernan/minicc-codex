# 文件回退与完成评估补充交付

日期：2026-09-18。此记录只描述本轮实际改动，工作区其他未提交改动仍保留。

## 文件回退

原先仅在任务开始复制 Git 脏文件，正常情况下最常修改的干净源码没有进入快照，无法兑现界面中的回退操作；根目录的 `manifest.json` 还会与快照清单重名。现在：

- 新格式将文件镜像放入 `files/`，清单原子替换；记录镜像 SHA-256，损坏的镜像跳过并返回原因类别。
- 编辑器在第一次写入、删除或移动前记录原内容。重复写入保留最早镜像，已捕获任务恢复运行不会覆盖原快照。`task_id` 通过线程和独立进程共用请求传递。
- 回退只操作记录为该任务实际修改过的文件；保留无关脏文件和之后新建的无关文件。该任务新建的文件仅在内容仍与任务最终输出一致时移除。
- 回退前核对当前文件与任务最后一次写入的摘要，发现用户后续修改时保留并返回 `conflicts`。未完成的写入记录也不会被猜测恢复。
- 工作区仍有排队或运行任务时拒绝回退，并与提交使用同一任务管理锁。界面遇到冲突或跳过时显示部分恢复及具体路径，避免把部分恢复显示为全部成功。
- 排除绝对路径、目录逃逸、Git/内部元数据路径和链接；不再静默截断第 400 个之后的脏文件。
- 快照上限为 400 个已复制文件、单文件 16MiB、总计 64MiB。超限或失败的文件记录 skipped/reason，摘要标注 partial、captured=false；惰性写入若无可靠镜像则拒绝修改，不把部分捕获宣称为全部成功。
- 复制前后核对源文件状态，备份写到临时文件后替换；首次及后续写入均拒绝覆盖中途外部修改。最后一次任务输出与当前内容不一致时，恢复也不会覆盖用户变化。

兼容旧快照的复制恢复。惰性镜像覆盖内置编辑器的写入、修改、移动和删除；任意 shell 或 MCP 工具自行修改文件不经过编辑器，不能宣称都能回退。此能力是文件恢复，不是 Git 索引、提交历史或目录事务恢复。

## 完成评估

- 追踪 `verification_results` 中各条检查的独立结局，一个测试通过不能掩盖另一个测试的失败。
- 配置文件、扩展名之外的源码、Dockerfile、requirements.txt、CMakeLists.txt 都需要实际验证，单纯重读不能作为代码行为验收。
- 异常 verification detail 类型不会令评估崩溃，也不会被误认为通过证据。
