## 实施顺序

1. A1–A3、B1–B4、D1–D3 独立并行；主线实现 C1/C3/A4/A5。
2. 集成共用契约及验证计划；落实 C2/D4/B5/E1，处理交叉影响。
3. 各工作包定向验证，模型调用用确定性 fake/mock 验证协议；评测工具不把 fake 成功率当真实模型能力。
4. 针对改动进行一次集成检查，检查关键任务提交、流式完成、恢复、构建、移动与主题；只因新失败扩大检查范围。
5. 记录实测结果、命令与边界，将每项状态更新为完成或明确的外部限制。

## 指标

- 基线：源码索引 0，摘要约 9.27 秒 / 77 次 git show，工作台 ready 10.95 秒，手机发送下沿超出视口 12px。
- 改进后记录：索引覆盖、命中路径、冷/热摘要时间、启动 ready、静态资源字节、定向及端到端结果。
- 真实模型准确率由独立行为评测输出，不从单元测试或假模型推导；保留不可用/未评分状态。
