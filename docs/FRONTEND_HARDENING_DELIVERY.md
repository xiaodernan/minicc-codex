## 任务生命周期收尾

继续检查跨工作区和并行请求，补齐以下可复现竞态：

- 提取 `core/scope.js` 管理异步视图所属工作区／会话。旧工作区的任务详情迟到后不会写入当前会话缓存；旧请求也不会删除新一轮加载的 pending。会话恢复的动画帧在切换后失效。
- 提交请求持有自己的令牌：第一个任务结束时不会解锁仍在提交的第二个任务。后台任务结束不再抢走用户当前弹窗／输入框焦点。
- 提交期间切换工作区，响应仍绑定原工作区；不会占用新工作区的 activeTaskId、忙碌状态或任务栏。切换前保存原会话视图。
- 终态 SSE 后补拉到仍为 running 的滞后快照时，以终态事件为准，防止错误完成显示或丢失回答。
- 回退会话请求使用发起时的会话与工作区缓存键，迟到响应不重绘后来打开的会话。
- 修正 `beforeunload` 直接传入事件作为会话 ID 导致错误缓存键的问题；“清空视图”使用与写入一致的工作区／会话键删除内存缓存。

验证：新增 `npm run test:lifecycle` 覆盖旧详情迟到、重叠提交、弹窗焦点、POST 期间切换工作区和终态顺序五组真实浏览器场景；全部通过。重新运行 `test:optimization` 和 `check:web` 通过，pageerror 为 0；最新模拟路由 ready 为 316–428ms，桌面／手机 × 亮暗四种组合均无横向溢出。未运行全量回归。

根任务补验：插入 10,000 个会话/终态键，BoundedMap/BoundedSet 分别保持 24/2048 的容量；活任务集合不淘汰。终态 SSE 均已 close，等待 3.7 秒（超过 3.5 秒快照超时）不再创建新连接。无绑定任务的轮询停止，迟到 onerror 不重新发起恢复。`test:lifecycle` 和真实 HTTP `test:web` 再次通过。

## 长任务与浏览器存储补充

继续检查大体量执行记录，修复了窗口滚动和缓存配额两个真实边界：

- 工具详情和阶段记录使用工具 item ID／事件 ID／序列作为稳定标识。超过 240 条时间线窗口后，记录索引变动不会误关原来的详情、错开另一条记录，或替换用户正在阅读的节点；同一工具 running → completed 的事件 envelope ID 变化时也维持身份。
- 流式文字和 usage 更新沿用事件数组；数组没有变化时直接跳过时间线序列化。新快照只比较有界的可见事件窗口，指纹放在 WeakMap 内，避免把完整工具输出复制进 HTML attribute／会话缓存。图标刷新局限于当前时间线。
- 浏览器持久化视图最多 24 项、总计 1,200,000 个字符、单项 180,000 个字符，写入时迁移并回收旧缓存。超过配额会回收最旧视图后重试，仅操作会话视图键；认证和主题设置保持不变。服务端仍保存完整记录，过大的单条消息不进入本地视图缓存。
- HTML 压缩按完整消息移除，避免反复序列化全部 DOM；切换到后台后完成的任务共用同一个缓存入口。

验证：新增 `npm run test:scale`，覆盖 261 条时间线滚动、同一工具换 envelope ID、嵌套详情展开状态、1000 次相同事件数组刷新、35 项旧缓存迁移、30 项新视图写入、超大消息和存储配额错误重试。结果通过：仅保留 239 个工具节点；1000 次刷新为 0 次序列化；缓存保持 11 项／1,100,209 字符，认证及主题未被回收。指标见 `output/playwright/frontend-scale-metrics.json`，该耗时是受控前端局部观测，不是端到端 SLA。

相关 `test:optimization` 四种视口与主题、`test:lifecycle`、`check:web` 通过，pageerror 为 0；未跑全量回归。新增测试已加入 CI 的前端定向检查。

根任务补充规模：输入10000条事件，渲染46.6ms、239个工具节点；1000条消息缓存后仍保留最新完整消息且小于18万字符。实际 HTTP 产品测试重复运行时先创建新任务，不清空服务端既有历史。
